PROJECT TRACKER - CODE EXPLANATION
====================================

BEVEL RECIPE
-------------
A bevel makes a flat rectangle look 3D by drawing coloured lines along its edges.
Think of light hitting from the top-left — top and left sides are bright, bottom and right are in shadow.

Sunken (like a text input — looks pushed into the screen):
  top and left edges = dark,  bottom and right edges = white

Raised (like a button — looks popping out of the screen):
  top and left edges = white,  bottom and right edges = dark

To draw it: after pygame.draw.rect, use pygame.draw.line along each of the 4 edges.
  top edge:    top-left corner  → top-right corner
  left edge:   top-left corner  → bottom-left corner
  bottom edge: bottom-left      → bottom-right
  right edge:  top-right        → bottom-right

Double bevel = draw two lines per edge, the second 1px inside the first with a slightly different shade.
The notes/todos and files boxes use: grey + black on top/left (shadow), white + XP-grey on bottom/right (highlight).


GRADIENT RECIPE
----------------
A gradient smoothly shifts from one colour to another across a rectangle.
pygame has no built-in gradient, so you draw it yourself as a series of thin strips.

Steps:
  1. Decide how many strips (bands) to split the rectangle into — more bands = smoother.
  2. Loop from 0 to bands.
  3. Each iteration, calculate the x position and width of the current strip.
  4. Calculate the colour for that strip by blending between the start and end colour:
       value = start + (end - start) * (i / bands)
     Do this for r, g, and b separately.
  5. Draw the strip with pygame.draw.rect using that colour.

Example — the title bar goes from dark navy (10, 36, 106) on the left to light blue (166, 202, 240):
  for i in range(bands):
      bx = win_w * i // bands
      bw = win_w * (i + 1) // bands - bx
      r  = int(10  + (166 - 10)  * i / bands)
      g  = int(36  + (202 - 36)  * i / bands)
      b  = int(106 + (240 - 106) * i / bands)
      pygame.draw.rect(window, (r, g, b), (bx, 0, bw, title_h))

The same pattern works top-to-bottom — just split by y instead of x.


VARIABLE GLOSSARY
------------------
General naming pattern:
  x, y    = position (left edge, top edge)
  w, h    = size (width, height)
  r, t, b = right / top / bottom edge (a single coordinate, not a size)

Layout:
  title_h      — height of the title bar (30px)
  SIDEBAR_X    — x where the sidebar ends and the main panel begins (150px)
  panel_w / pw — width of the main panel (window width minus sidebar)
  divider_y    — y of the horizontal line splitting sidebar into projects (top) and tags (bottom)
  offset       — how many pixels the main panel content has been scrolled down

Box sizing (used in loops that draw project/tag boxes):
  text_w, text_h — pixel width and height of a piece of text, from font.size()
  rw, rh         — width and height of a bevel box: text size + a few pixels of padding

Loop variables:
  enumerate(list) — a built-in that gives you both the index AND the item as you loop.
   instead of:  for item in list          (item only)
    you write:   for i, item in enumerate(list)  (index + item)
  i — the index (position number) of the current item in the loop.
   i=0 means first item, i=1 means second, etc.
   useful for knowing WHICH item you are on, e.g. to compare with selected.

Text input:
  typing          — True when the user is currently editing a project name
  text_buffer     — the letters the user has typed so far
  last_click_time — the time (in milliseconds) of the last click on a project card
  last_click_i    — which project was last clicked (used to detect double-click on the same card)
  name_rect       — a clickable rect around the project name in the main panel

  Double-click works by checking two things at once:
    1. the same card was clicked twice (last_click_i == i)
    2. the two clicks were less than 300ms apart (pygame.time.get_ticks() gives the current time in ms)

Plus buttons:
  px, py   — position of a + button (top-left corner)
  pbw      — width of the projects + button  (pbw_t for the tags one)

Progress bar:
  bar_h      — height of the grey track
  progress_W — pixel width of the green fill (track width × progress value)
  bt, bb     — y of the track's top and bottom bevel lines (already adjusted for scroll offset)
  bf, bfb    — y of the fill's top and bottom bevel lines (same idea, 2px inside the track)

Combobox (the tags dropdown):
  cx, cy, cw, ch — x, y, width, height of the whole combobox
  btn            — width of the small dropdown button on the right side
  bx             — x where the dropdown button starts (cx + cw - btn)
  ax, ay         — center point of the triangle arrow inside the button

Fade divider lines:
  line_y     — y position of a section divider line
  fade_dist  — how many pixels the line fades over (shorter = sharper, longer = softer)
  xi         — current x pixel being drawn as the fade loop steps across

Resize / drag state:
  resize_start_w/h  — window size at the moment a resize began
  resize_delta_x/y  — how far the mouse has moved since the resize started (Linux only)
  drag_start_win_x/y  — window position when dragging started
  drag_start_abs_x/y  — absolute screen cursor position when dragging started


LINES 1-16: Imports & Init
---------------------------
Imports pygame (graphics/window library), sys (for exiting), subprocess (for restarting the app),
ctypes (for low-level OS calls), and platform (to detect the OS).
pygame.init() starts up all pygame systems.
IS_WINDOWS detects whether the app is running on Windows or Linux.
On Windows, ctypes.wintypes is imported for native window move/resize via the Windows API.
On Linux, pygame._sdl2 and libSDL2 are imported to handle the same operations cross-platform.

LINES 18-20: Window Setup
--------------------------
Creates a 600x600 pixel window with no frame (no title bar or borders — we draw our own).
Sets the window title to "project tracker".

LINES 22-29: Project Data
--------------------------
A list of 3 projects. Each project is a dictionary with a name, status, list of tags,
and a progress value between 0 and 1 (so 0.50 = 50% done).
all_tags is a standalone list of every tag — independent of projects so tags can be
added/removed without touching the project data.

LINES 29-31: Fonts
-------------------
Loads two sizes of the Tahoma font — small (13px) for most text, big (16px) for headings.
Tahoma is the font Windows XP used throughout its UI.

LINES 33-56: Layout & State Variables
--------------------------------------
SIDEBAR_X = 150: the sidebar takes up the left 150 pixels.
win_w, win_h: the current window width and height.
panel_w: the width of the main content area (window width minus sidebar).
run: keeps the main loop going — set to False to quit.
offset: how far the content has been scrolled down.
dragging, drag_offset_x/y: tracks whether the user is dragging the window and where they grabbed it.
resizing_right, resizing_bottom: tracks whether the user is resizing from the right or bottom edge.
resize_start_w/h, resize_delta_x/y: on Linux, stores the window size at the start of a resize
  and accumulates how far the mouse has moved, so the final size can be applied on mouse release.
drag_start_win_x/y, drag_start_abs_x/y: on Linux, stores the window position and absolute cursor
  position at the moment dragging starts, so the window can follow the cursor correctly.

LINE 62: Main Loop
-------------------
Everything from here to the end runs ~60 times per second (once per frame).

LINE 63: Frame Rate Limiter
----------------------------
Pauses for 16 milliseconds each frame, giving roughly 60 frames per second.

LINES 65-68: Clickable Zones
------------------------------
close_rect: a small rectangle in the top-right corner — clicking it closes the app.
refresh_rect: the blue button just to the left of close — clicking it restarts the app.
right_edge: a thin strip along the right side of the window — used to detect resize dragging.
bottom_edge: a thin strip along the bottom — same idea for vertical resizing.

LINES 70-71: Windows Handle
-----------------------------
On Windows only, gets the native window handle (hwnd) — a low-level ID used by the
Windows API to move and resize the window via ctypes.

LINES 73-174: Event Handling
------------------------------
Loops through all events that happened since the last frame:

  QUIT: If the user closes the window normally, stop the loop.

  KEYDOWN: A key was pressed — no action yet (placeholder for future keyboard logic).

  MOUSEWHEEL: Scrolling the mouse wheel moves content up or down by 20 pixels per
  tick, but only when the mouse is over the main panel (not the sidebar). The offset is clamped
  so it can't go above 0 (can't scroll past the top) or past the bottom of the content.

  MOUSEBUTTONDOWN: On a left click:
    - If the X button was clicked, quit.
    - If the R button was clicked, launch a new copy of the script with subprocess.Popen
      (Popen doesn't block — it starts the new window and immediately moves on),
      then set run = False to close the current window.
    - If the projects + button was clicked, append a new blank project to the list.
    - If the right edge was clicked, start resizing horizontally.
    - If the bottom edge was clicked, start resizing vertically.
    - If the click was in the title bar area (top 35px), start dragging the window.
      On Linux, also records the absolute cursor position and window position so
      dragging can be calculated correctly.

  MOUSEMOTION: While the mouse is moving:
    - If not doing anything special, change the cursor to a resize arrow when hovering
      over the window edges, or back to the normal arrow otherwise.
    - If resizing right/bottom on Windows: uses the Windows API to stretch the window live.
      On Linux: accumulates how far the mouse has moved but doesn't resize until mouse up.
    - If dragging on Windows: uses the Windows API to move the window to follow the cursor.
      On Linux: uses SDL2 to get the absolute cursor position and moves the window accordingly.

  MOUSEBUTTONUP: When the mouse button is released:
    - If a resize just finished on Windows: reads the final size from the Windows API and applies it.
      On Linux: adds the accumulated mouse delta to the starting window size to get the final size.
      Both enforce a minimum size of 200x100.
    - Reset all drag/resize flags and restore the normal cursor.

LINES 176-189: Recalculate Layout
-----------------------------------
After handling events, recalculate win_w/win_h (in case the window was resized),
then work out panel dimensions. Also reads the progress value for the selected project
(currently always project 0) and calculates how wide the progress bar fill should be.
progress_W is capped at panel_w-22 so the green fill never overflows the grey track.

LINES 191-212: Draw — Background
----------------------------------
Fills the whole window with the XP cream color, then draws the blue gradient title bar
(30 vertical strips shifting from dark navy on the left to light sky blue on the right),
a thin highlight line at the very top, the title text, and fills the sidebar and main panel.

LINES 214-247: Draw — Chrome
------------------------------
Draws the outer window border (raised bevel: white top/left, dark bottom/right),
the beveled vertical divider between sidebar and panel, the beveled horizontal divider
that splits the sidebar into projects (top) and tags (bottom), the red close button with
an "X", and the blue refresh button with an "R". Both buttons center their label using
the text surface's width and height.

LINES 262-318: Draw — Sidebar
-------------------------------
Projects section: loops over the projects list and draws each one as a sunken beveled box.
After the loop, draws a fixed "+" button in the top-right corner — clicking it appends a new project.
Tags section: loops over all_tags and draws each tag the same way.
After that loop, draws a second "+" button in the corner of the tags section — clicking it appends a new tag.
Both + buttons are raised bevel (opposite of the project/tag boxes) so they look pressable.

LINES 320-336: Clip Region & Fade Lines
-----------------------------------------
Sets a clipping rectangle so that anything drawn outside the main panel is invisible
(prevents scrolling content from overlapping the sidebar or title bar).
Then draws 4 horizontal divider lines, each fading from blue on the left to white on the right.
Each line is 3px tall. Layout rule: label → divider (+17px) → content (+5px) → next label (+20px).

LINES 338-343: Section Labels
-------------------------------
Draws the project name in large text, and the "tags", "notes / todos", "files", "links"
section labels. All y positions subtract offset so they move when you scroll.

LINES 345-383: Boxes & Combobox
---------------------------------
Notes/todos and files boxes use a double sunken bevel — grey + black on top/left (shadow),
white + XP grey on bottom/right (highlight) — to look like classic 90s text input areas.
The tags combobox has the same sunken border for the text area, plus a raised dropdown button
on the right side with a small filled triangle arrow centered inside it.

LINES 385-408: Draw — Progress Bar
-------------------------------------
Draws the progress bar inside the clip region so it scrolls with the content.
Four helper variables (bt, bb, bf, bfb) hold the y positions of the track top/bottom and
fill top/bottom, all already adjusted by offset, so the bevel lines stay in sync.
The grey track uses a sunken bevel (dark top/left, white bottom/right).
The green fill uses a raised bevel with dark green shadows (0,100,0) on the bottom and right
so the edges contrast clearly against the grey track instead of blending into it.

LINE 410: Update Display
-------------------------
Resets the clip region so the sidebar draws correctly next frame, then pushes everything
drawn this frame to the screen. Without this, nothing would appear.

LINES 414-415: Cleanup
-----------------------
When the loop ends (run = False), shuts down pygame and exits the program cleanly.
